## Role
- You are a senior full-stack engineer and an expert in Computer Science, Artificial Intelligence, Python, LLM and UI/UX design.

## Project Context
- You are working on a cross-platform desktop application.
- The application is used to translate files into 40+ languages.

## Technology Stack

## Coding Standards
- **Programming Style:** Prefer functional programming to object-oriented programming.
- **Database Operations:**
    - Always use the `@db_transaction` decorator in `src/core/database.py` to handle connections and cursors.
    - Never execute direct sqlite3 queries in the UI layer; always use or create batch/helper functions in `src/core/database.py`.
    - The decorator supports nested calls; you can pass a `cursor` as the first argument to share a transaction.
    - Use batch helpers (`batch_pause_history_entries`, `batch_resume_history_entries`, `batch_retranslate_history_entries`, `batch_mark_deleting_history_entries`) for multi-row status updates.
    - Use `find_glossary_entry_by_source(set_id, source)` for case-insensitive lookup of an existing glossary entry in a set (powers the Glossary page's duplicate-on-Add replace/skip prompt).
    - Use `update_history_file_name()` to rename a history entry's `file_name` column (e.g. after legacy → modern format conversion).
    - `get_db_path()` includes a runtime safeguard that prevents tests from accidentally touching the production database.
    - SQLite is configured in WAL mode for crash resilience.
    - Errors are automatically logged via the `database` logger; avoid using `print()` for DB errors.
    - The `history` table (Translate Document) carries BOTH `error_code INTEGER` AND `error_message TEXT`.  `error_code` drives the localised template (mapped via `_ERROR_TR_KEYS`); `error_message` preserves the raw engine tag including any `:Service` suffix so the UI can render service-aware copy ("Invalid Gemini API key" instead of generic "Invalid API key") via `display_error_message()`.  Pass both to `update_history_status(h_id, status, error_code=..., error_message=str(exc))` from translator callsites; missing `error_message` (legacy DB rows from before the column existed) falls back to `get_error_message(error_code)`.  `batch_resume_history_entries` / `batch_retranslate_history_entries` clear BOTH columns so a retry starts from a clean error state.  The sibling history tables (`extraction_history`, `subtitle_history`, `voice_history`, `dubbing_history`) have always had `error_message TEXT` — this brings the Translate Document table into parity.

- **LLM Engine** (`src/core/llm_engine.py`):
    - **Two providers, two SDKs.** Custom (OpenAI-compatible) goes through the official `openai` SDK; Gemini goes through `google-genai`. Construct each via `_build_openai_client(api_key, endpoint)` / `_build_gemini_client(api_key="")` — never instantiate the client class directly so the per-call defaults (timeout, headers, retry policy) stay consistent.
    - `_build_openai_client` sends both `Authorization: Bearer` AND `api-key` headers so the same client works against OpenAI / OpenRouter / vLLM / Anthropic-OpenAI-shim / Azure without per-provider tuning. SDK constructed with `max_retries=0` because `@retry_api_call` owns retry semantics — never let the SDK's built-in retry overlap.
    - `_build_gemini_client` reads `llm/gemini_use_vertex`. When set, dispatches to `genai.Client(vertexai=True, project=..., location=..., credentials=...)` instead of `genai.Client(api_key=...)`. Vertex credentials come from `llm/vertex_credentials` (service-account JSON path) when set, otherwise Application Default Credentials. Raises `AUTH_ERROR` early when project missing OR credentials file unreadable.
    - **Custom-endpoint API choice** is auto-detected: `_classify_custom_endpoint()` returns `(explicit_api, base_url)`. If the user pasted `/chat/completions` we use only chat; if `/responses` we use only responses; if a bare base URL we try chat first and fall back to responses on `INVALID_REQUEST`, then cache the choice in `_CUSTOM_API_CACHE` (keyed via `_custom_cache_key(endpoint, model)` — a canonical-form helper that routes both caches through `_classify_custom_endpoint` so trailing-slash, whitespace, missing scheme, and `/chat/completions` vs `/responses` vs bare base URL all collapse to one key) so subsequent calls skip the wrong API entirely while a genuine endpoint change (different host) still invalidates correctly. Cache cleared between tests via the conftest autouse fixture. **Both-failed error preference**: when chat exhausts variants AND the responses fallback also fails, the dispatcher surfaces the *more actionable* error rather than always re-raising the chat `INVALID_REQUEST`. If the responses error is in the informative set (`TIMEOUT_ERROR`, `CONNECTION_ERROR`, `SERVICE_UNAVAILABLE_ERROR`, `QUOTA_ERROR`, `AUTH_ERROR`, `MODEL_NOT_FOUND`, `REQUEST_TOO_LARGE`), that one wins — the user's real problem is the network / quota / credentials, not a benign "chat doesn't accept this payload" signal. Otherwise (responses also returned a generic `INVALID_REQUEST`) the chat error is preserved.
    - **4-variant payload fallback** in `_translate_custom_chat`: `json_object+temperature` → `temperature_only` (drops `response_format` for providers that reject it) → `minimal` (drops `temperature` for reasoning models like o1/o3/gpt-5.x) → `no_system_role` (merges system into user message for Azure deployments that reject `role: system`). Each fallback logged at WARNING (not INFO — `pdf_processor` silences INFO on the `llm` logger during runs). The first successful variant is cached in `_CUSTOM_VARIANT_CACHE` keyed on `(endpoint, model)` so the next call for the same model starts from the working variant instead of re-paying 2-3 failed 400s; on a stale-cache miss (provider config changed), the dispatcher falls through to the remaining variants in original order and rewrites the cache on success. Cleared between tests by the conftest autouse fixture alongside `_CUSTOM_API_CACHE`. The cache-hint reorder logic is shared with `_call_custom_chat_with_fallback` via `_reorder_variants_for_cache_hit(variants, cache_key)` — moves the cached-winner variant to position 0; remaining variants stay in original order; identity-returns the input list when the cache key is missing OR the cached label isn't in this caller's variant list (graceful no-op for the `no_system_role`-from-translation-chain scenario the 3-variant one-shot helper doesn't know about).
    - **Shared one-shot variant fallback** via `_call_custom_chat_with_fallback(client, *, model, endpoint, messages, timeout=None)`: same chain as `_translate_custom_chat` minus the `no_system_role` step (one-shot callers send a single user message with no system role to merge). Used by every non-streaming Custom-chat callsite that isn't translation: `_extract_text_custom` (Extract Text vision) and `_translate_image_custom` (PDF/Office embedded image translate). Reads/writes the same `_CUSTOM_VARIANT_CACHE`, so the working variant for `(endpoint, model)` discovered by translation also short-circuits the vision / extract calls (and vice versa). Without this helper, a reasoning model like Azure `gpt-5.2-chat` that rejects `temperature: 0.0` would 400 on the first vision attempt and raise on every call.
    - **Streaming variant fallback** via `_stream_custom_chat_with_fallback(client, *, model, endpoint, messages, timeout=None)`: returns the SDK stream iterator after running a 2-variant pre-stream fallback (`temperature_only` → `minimal`). Skips the `json_object+temperature` variant because streaming responses are plain text (no structured output). Used by `_stream_custom` (translate-text streaming + Listen button + live mode). **Reads** `_CUSTOM_VARIANT_CACHE` for hints (cached `minimal`/`no_system_role` → skip the temperature attempt) but does **not write** — round-tripping a streaming-discovered label would corrupt the non-streaming callsite's payload choice (cache labels reflect non-streaming payload shapes that include `response_format`). The 400 happens at `chat.completions.create()` time, before any chunks yield, so payload variants can be retried pre-stream; once a stream object is returned, the caller iterates normally and chunks already yielded can't be rolled back.
    - **Reasoning-model `<think>` stripping**: `_strip_think_blocks(text)` removes both closed `<think>...</think>` blocks AND any *unclosed* `<think>` opener (model truncated by `max_tokens` mid-reasoning before producing the answer). Reasoning models always emit `<think>` as the first generated token (Qwen3 reasoning, Gemma, DeepSeek-R1, GLM-Z1, Magistral), so the over-eager "sweep to end on unclosed opener" is safe. The unclosed-block branch logs a WARNING pointing the user at `max_tokens` so they get a real diagnostic instead of an opaque `INVALID_RESPONSE`. All 8 non-streaming response-parsing callsites (chat translation, responses-API translation, vision/extract, image translation) route through this helper. Streaming text uses `_strip_think_tags()` — a buffer-aware generator that handles `<think>` split across SSE chunks; on stream-end while still inside an unclosed `<think>` it logs the same WARNING (symmetric with the non-streaming path) and yields nothing rather than emitting partial reasoning.
    - **Cross-session persistence**: both caches survive app restart via `llm_endpoint_cache.json` under `path_manager.get_llm_endpoint_cache_path()` (cache dir, schema-versioned via `_CACHE_SCHEMA_VERSION`, `|`-joined string keys). `_persist_caches()` is called on every cache mutation; `_load_persistent_caches()` is **opt-in** — each production entry point (`main.py`, `cli.py`, `mcp_server._bootstrap()`) calls it once at startup; tests skip the call so they start with empty caches without needing path patching during the brittle pre-fixture import phase. Conftest still redirects `get_llm_endpoint_cache_path` to a temp dir so tests that exercise `_translate_custom` don't write to the user's real cache file. A future-/older-schema file is silently discarded so a forward-compat field can never poison the current process.
    - **Cold-start write coalescing**: `_translate_custom_chat` accepts `defer_persist=True`; the ambiguous-endpoint dispatcher in `_translate_custom` snapshots the variant cache value before calling chat, then flushes ONE `_persist_caches()` covering both the variant write and the api-cache write after success. Cold start = 1 disk write (down from 2); cache-hit calls = 0 writes (snapshot equality short-circuits). The explicit `/chat/completions` short-circuit path doesn't pass `defer_persist` (extremely rare, not worth the complexity).
    - **Persistence concurrency model**: `_CACHE_LOCK` is a `threading.RLock()` (reentrant — every cache mutator acquires it across the precheck-and-mutate before invoking `_persist_caches`, which re-acquires the same lock internally for its own read-merge-write). `_persist_caches()` (a) reads the on-disk file first and merges its entries *underneath* the in-memory dict so a sibling process / earlier session's writes survive an overwrite (in-memory wins on key collision because the local process is authoritative for what it just observed); (b) `tempfile.mkstemp`s a unique tmp filename in the cache dir per writer so two simultaneous persists never trample each other's pre-rename file; (c) catches `(OSError, TypeError, ValueError)` so a corrupted in-memory dict can't crash a translation request — failures are logged at WARNING and the orphan tmp (if any) is cleaned up via `contextlib.suppress(OSError)`. `_decode_cache_payload()` is shared by both load and read-merge-write so the validation rules (schema version, isinstance checks, canonical-key reconstruction) live in one place.
    - **Responses API parsing**: `_translate_custom_responses` uses the SDK's `response.output_text` accessor with a fallback that walks `output[*]` for older/preview shapes. `_extract_json_object` also handles JSON wrapped in `` ``json `` fences (some models emit those when `response_format` isn't honoured).
    - `translate_text()` uses token-budget-based batching (`TOKEN_BUDGET` in `src/constants/llm.py`) instead of fixed batch sizes. Items are grouped dynamically by estimated token count via `_split_by_token_budget()`.
    - `translate_text()` filters untranslatable content (numbers, URLs, emails, file paths) via `_is_untranslatable()` and deduplicates repeated strings via `_deduplicate_texts()` / `_restore_duplicates()` before sending to the LLM, reducing token usage.
    - Glossary entries are compressed per API call via `_compress_glossary()`: only entries whose source or target term appears in the current batch text are included in the prompt. Matching is case-insensitive and accent-insensitive via `normalize_for_search()` from `text_utils.py`.
    - All LLM API errors are handled by `_handle_api_error()`, which raises `ValueError` with a tag string (e.g., `"AUTH_ERROR"`, `"QUOTA_ERROR"`). Recognises `openai.*Error` subclasses and `google.genai.errors.APIError`. Order matters: genai is checked first so that an `APIError` carrying a 408/504 status code maps via `_HTTP_ERROR_MAP` rather than getting swallowed by a generic `TimeoutError` branch; openai SDK exceptions follow so `APITimeoutError` takes precedence over the bare `TimeoutError` clause.
    - HTTP status codes are mapped via `_HTTP_ERROR_MAP` (one map shared by both SDKs).
    - Use the `@retry_api_call(max_retries=3, base_delay=3.0)` decorator on LLM API functions for automatic exponential backoff on transient errors (`SERVICE_UNAVAILABLE_ERROR`, `TIMEOUT_ERROR`, `CONNECTION_ERROR`). Non-transient errors (e.g., `AUTH_ERROR`, `QUOTA_ERROR`) are raised immediately without retry.
    - `translate_batch()` translates a flat list of strings in groups of `TRANSLATION_BATCH_SIZE`. Supports checkpoint-based resumption: previously-translated batches are loaded from disk and only uncached items are sent to the LLM. Checkpoints are only saved when the LLM returns the expected number of results to avoid persisting untranslated originals. Accepts `provider` and `model` kwargs that are forwarded to every per-batch call so `TranslationConfig.llm_provider/llm_model` (resolved from per-feature settings via `from_settings(model_setting_key=...)`) reaches the engine — every output path (PDF, Office, EPUB, text, MCP) must thread these kwargs through; dropping them silently routes to the global default model.
    - In `translator.py`, `_map_error_to_code()` converts tag strings to numeric `ERR_*` codes from `src/constants/errors.py` for DB storage.
    - `extract_image_text()` sends an image to the configured LLM vision provider and returns the extracted text (no translation). Dispatches to `_extract_text_gemini()` or `_extract_text_custom()` based on `SETTING_LLM_METHOD`. Uses `LLM_TEMPERATURE` for deterministic extraction.
    - **Multi-provider compatibility**: any OpenAI-compatible endpoint works through the Custom provider. Verified working: OpenAI direct, Azure OpenAI (chat + Responses-only deployments), Anthropic via `https://api.anthropic.com/v1/`, DeepSeek via `https://api.deepseek.com/v1`, OpenRouter as a hub for ~300 models, Groq / Together / Mistral / Cohere / Fireworks, plus local servers (vLLM / Ollama / LM Studio). The 4-variant fallback + dual-header auth + chat/responses dispatch absorb every provider-specific quirk we've encountered.

Workers constructed with an explicit `_config` snapshot opt out of this refresh.

Empty substitution when no recognised package manager is detected.

    - **Live engine tests**: Cover silence detection threshold boundaries, max buffer forcing, concurrent `send_audio()` from multiple threads, malformed WebSocket tokens/responses, reconnection state cleanup, and session timeout handling for both engines (LiveTranscriber, SonioxTranscriber).
    - **Full-suite reliability**: A single-process serial run (`uv run pytest`) accumulates PySide6 / pytest-qt native bookkeeping (queued events to deleted receivers, lingering signal connections, etc.) and segfaults around the 6,000-test mark inside `pytestqt.plugin._process_events`. The fix is per-test process isolation via the `pytest-forked` plugin (in the `dev` dependency group): `uv run pytest --forked` runs each test sequentially in its own subprocess so accumulated state can't bridge tests. ~6× slower than serial, but reliable. For day-to-day work, run only the touched test file (always clean); reserve `--forked` for release-gate smoke runs.
    - **Forked-mode Qt geometry gotcha**: under `--forked`, `window.resize(w, h)` on an unshown widget can be lost — the offscreen platform's initial smaller size already fired a resize event before our resize lands, and the follow-up event gets swallowed. Tests that depend on a specific window width (e.g. sidebar collapse/expand hysteresis) must synthesise a `QResizeEvent` and dispatch it directly to `window.resizeEvent` instead of relying on `resize()` alone. The pattern lives in `tests/test_window.py`'s `main_window` fixture and `_trigger_resize` helper.
    - **LLM-tab settings tests**: the LLM settings tab now lazy-imports `load_custom_providers` and renders one section per stored entry — there is no static "Custom" section. Tests that need the Name / API key / Endpoint / Models fields on screen must seed a stub provider; `tests/test_settings_page.py` ships a `_patch_custom_providers()` helper for this. Don't add `load_custom_providers` to the shared `_SETTINGS_PATCHES` dict — `TestCustomProviderName` deliberately uses the real keychain-isolated path and would break.
